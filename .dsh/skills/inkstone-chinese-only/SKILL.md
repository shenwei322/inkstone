# 强制中文交流（InkStone 项目规范）

本项目的作者与维护者使用**简体中文**交流。本 skill 适用于本项目内的**每一次**交互，不需要用户显式点名。

## 铁律

### 1. 思考过程必须用中文

内部推理（thinking / reasoning / 思维链）**全部用简体中文书写**。

- 即使是英文提问，思考也用中文。
- 不要中英混排思考；技术名词可保留英文原词（见 §4）。
- 不要在思考里写英文整句，例如 "Let me check the file first" → 应写「先看一下这个文件」。

### 2. 面向用户的回复必须用中文

所有面向用户的输出一律简体中文，包括：

| 场景 | 要求 |
|---|---|
| 最终回复 | 全中文，不得整段英文 |
| 中间进度说明 | 中文 |
| 提问 / 澄清 | 中文 |
| 任务清单、待办列表 | 中文 |
| 错误解释与排障结论 | 中文 |
| 代码评审意见 | 中文 |

### 3. 用户用英文提问也要用中文回

用户语言**不**改变本规则。英文提问 → 中文思考 + 中文回复。不要因为提问是英文就切换成英文回答。

### 4. 这些保留原文，不要翻译

以下内容**保持原样**，不要强行汉化：

- **代码本身**：标识符、函数名、变量名、类型名
- **命令与参数**：`go vet ./...`、`docker compose up -d`
- **文件路径与 URL**
- **报错原文**：引用报错时保留英文原文，可在其后用中文解释
- **库/框架/协议名**：Go、Gin、GORM、PostgreSQL、Next.js、React、GSAP、JWT、CORS、Tailwind CSS
- **代码注释**：跟随该文件既有风格；写新注释时优先中文（本仓库注释以中文为主）

### 5. 项目既有产物也必须是中文

本仓库面向用户的文案已经是中文，新增时保持一致：

- 后端错误提示：`NewValidationError("中文提示")`，见 `internal/handler/errors.go`
- API 返回的 message 字段
- 前端界面文案
- Git 提交信息：中文
- 文档（`.ai-skill/`、`README`、发布说明）：中文

## 自检（每次回复前）

发送前快速过一遍：

1. 我的**思考**是中文吗？
2. 我的**回复**是中文吗？
3. 有没有整段英文句子漏出来？（引用报错原文、代码、命令除外）
4. 用户是英文提问吗？→ 我仍然用中文回答了吗？

任一项为「否」，立即改写后再输出。

## 常见错误

| 错误做法 | 正确做法 |
|---|---|
| 用户用英文问，就用英文答 | 一律中文答 |
| 思考用英文、回复用中文 | 思考也必须是中文 |
| 整段英文解释后附一句中文总结 | 全篇中文，英文仅限代码/术语/报错原文 |
| 把技术名词硬译成中文（如「金」= Gin） | 保留 `Gin` 等原名 |
| 提交信息写成英文 | 提交信息用中文 |
